# Troubleshoot (트러블슈팅)

버그, 이슈, 에러를 체계적으로 진단하고 근본적으로 해결합니다.
CLAUDE.md의 Problem Solving, Technical Debt 원칙을 기본으로 따르며, 아래는 트러블슈팅 특화 규칙입니다.

## 원칙

1. **근본 원인 해결**: 증상만 가리는 수정 금지. 근본 원인을 찾아서 심플하게 해결할 것.
2. **웹 검색 활용**: 원인이 불분명하면 웹 검색으로 알려진 이슈/해결책을 먼저 조사.
3. **심플한 해결책 우선**: 여러 해결책이 있을 때 가장 단순한 것부터 시도.
4. **수정 전 검증**: 수정 전에 `/multi-review`로 사이드 이펙트, 엣지 케이스를 검증.
5. **프레임워크 버그 예외**: 프레임워크/라이브러리 버그로 확인된 경우, 공식 이슈 링크를 주석에 기록하고 최소 범위 워크어라운드를 허용.

## 워크플로우

### Step 1: 현상 파악

- 에러 메시지, 스택 트레이스, 재현 조건을 정확히 파악
- 이슈가 어떤 범위에서 발생하는지 확인 (특정 파일? 특정 디바이스? 특정 조건?)
- 재현이 안 되면: 로그 분석, 환경 차이 비교(OS, 프레임워크 버전, 디바이스)

### Step 2: 원인 조사

- 관련 코드를 읽고 로직 흐름을 추적
- 웹 검색으로 프레임워크/라이브러리의 알려진 이슈 및 커뮤니티 해결책 확인
- 필요 시 임시 로그를 추가해서 실제 값을 확인

### Step 3: 해결책 설계

- 가능한 심플한 해결책을 설계
- `/multi-review`로 해결책의 정확성, 사이드 이펙트, 엣지 케이스 검증
- 코드 수정 시 프로젝트 코드 스타일 및 관련 가이드라인 스킬 준수

### Step 4: 수정 및 확인

- 수정 적용 후 빌드/analyze 통과 확인
- 반드시 AskUserQuestion으로 해결 여부 확인:

  ```text
  "이슈가 해결되었나요?"
  - "해결됨" — 다음 작업으로 이동
  - "여전히 재현됨" — Step 2로 돌아가서 재조사 (같은 접근법 반복 금지, 원인 재분석 필수)
  - "다른 이슈 발생" — 새 이슈로 Step 1부터 시작
  ```

- 해결 확인 없이 세션을 종료하거나 다음 작업으로 넘어가지 말 것

### Step 5: 정리

- 임시 디버그 로그 제거
- 해결 과정에서 생긴 불필요한 코드 정리
- 재발 가능성이 있는 이슈(프레임워크 버그, 환경 특이사항)는 메모리에 기록

## 금지 사항

- 원인 파악 없이 코드를 이리저리 바꿔보는 시행착오
- 해결 확인 없이 다음 작업으로 넘어가기
- 같은 접근법으로 동일 수정을 반복 (실패 시 원인 재분석 필수)
